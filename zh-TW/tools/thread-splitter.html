X 和 Threads 貼文串拆分工具

貼上一段單則貼文放不下的內容，即可得到一個按句子邊界斷句、編號排列的貼文串，長度適配 X 允許的 280 個字元或 Threads 的 500 個字元。

最後更新： 2026-08-03

手動拆分一篇長文草稿，是那種看起來只要兩分鐘、實際卻要花二十分鐘的活。你數到 280 個字元，正好落在一個分句中間，於是挪動斷句點，結果整個貼文串的編號全亂了，因為你在中間插入了一則貼文。

這個拆分工具替你做這些計算。它按段落和句子而不是字元流來讀取你的文本，儘量把完整的句子塞進每則貼文，只有當單個句子本身就超過字數上限時才會在句子內部斷開。編號是最後才加上的，並且計入與正文相同的字元預算，這正是大多數手動拆分容易出錯的地方。

一切都在你的瀏覽器中執行。不需要帳號，不需要上傳，我們這邊也不會保留你草稿的任何副本：你貼上的文本只留在你正在看的這個頁面裡。

X 和 Threads 上的限制

兩個網路都對單則貼文設有上限，超出的內容需要拆成一條鏈。區別在於每個字元的計費方式： X 會改寫連結並對其收取固定費用，Threads 則按網址的每一個字元原樣計費。

限制已於 2026-07-31 核實。Threads 沒有傳統的話題標籤區塊：每則貼文只帶一個話題標籤，其文字同樣計入 500 字元的上限。

貼文串編號慣例

編號是一種閱讀提示，而不是形式： 它告訴讀者在決定是否開始閱讀之前還剩多少內容。它也是純文本，所以無論你選擇哪種樣式，都會按和正文一樣的限制計費。

不編號

當每則貼文都需要單獨成立時使用，例如你預期單則貼文會被脫離上下文轉發。你會失去閱讀提示。

這個代價不大，但每則貼文都要付出。在 X 上，一個"12/14 "字首會從全部 14 則貼文中各佔去 6 個字元，合計消耗 84 個字元的篇幅。拆分器會在打包之前先預留出這部分空間，並且當你的文本一則貼文就能裝下時，會完全省去編號。

寫一則能被讀完的貼文串

  • 把第一則貼文放在最後寫。它是大多數人在資訊流裡唯一能看到的一條，所以它必須能作為一句獨立的陳述成立，而不是一句話的前半段。
  • 貼上之前，在段落之間留一個空行。拆分工具會把段落分隔當作強烈的提示，只要下一句放不下，就會在那裡開始新的一則貼文。
  • 把貼文串控制在讀者能讀完的長度。五到十則貼文是大多數貼文串能留住注意力的範圍；超過十五條，完讀率會急劇下降，最後幾條几乎沒人會讀。
  • 編號不是免費的。在 X 上，"12/14 "這樣的字首會在每一則貼文上佔用你 280 個字元中的 6 個，所以如果貼文串的字數緊張，可以換成"1/ "或者乾脆關閉編號。
  • 把連結放在最後一則貼文，而不是第一條。無論放在哪裡，一個 URL 在 X 上都要佔用 23 個字元，而放在第一條裡的連結，會在別人還沒讀到任何內容之前就給他們一個離開的地方。
  • 發布之前先讀一遍拆分結果。工具是按句子斷開的，但只有你知道哪一句才是值得單獨佔一則貼文的點睛之筆。

常見問題

編號會計入字元上限嗎？

會。在 X 和 Threads 看來，"3/12 "這樣的字首就是普通文本，所以它和其他內容一樣要佔用字元。這個拆分工具會在排版之前，先為貼文串中最長的字首預留空間，如果加上編號後所需的貼文數量發生變化，就會重新排版。

X 上的連結是怎麼計算字元的？

每個 URL 都會透過 t.co 重寫，無論原始連結有多長，都統一按 23 個字元計算。當你選擇 X 時，拆分工具會應用這一計算方式，所以一條包含 180 個字元追蹤連結的貼文，會按 X 的計算方式來測量，而不是按你文本編輯器的方式。

我的文本會被上傳或儲存在什麼地方嗎？

不會。拆分在你的瀏覽器中透過 JavaScript 完成，沒有任何內容會發送到伺服器，也不會被儲存。關閉標籤頁，草稿就消失了。

一個貼文串應該有多少則貼文？

大多數主題五到十條就夠。這個長度足以展開一個想法，也足夠短，讓人能讀到最後。如果你的草稿拆出了二十五則貼文，最誠實的做法通常是把它發布成一篇文章，再用一個簡短的貼文串來吸引點選。

拆分工具會在哪裡斷開文本？

優先在句子邊界斷開，並且段落邊界的優先順序高於句子邊界。只有當一個句子本身就比一整則貼文還長時，才會在句子內部斷開，而且是在空格處斷開，而不是在單詞中間。表情符號和旗幟圖案永遠不會被從中間拆開。

同一份草稿可以同時用於 X 和 Threads 嗎？

可以，但要切換平台開關，兩邊都檢查一遍。Threads 每則貼文給你 500 個字元，而 X 只有 280 個，所以同樣的文本在 Threads 上通常會拆成大約一半數量的貼文，斷句位置也會不同。
